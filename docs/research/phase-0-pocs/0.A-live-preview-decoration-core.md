## 本轮已证实

### inactive-rendered / active-source

使用仓库现有 `@codemirror/lang-markdown` 解析器和 `@codemirror/view` Decoration API：

- inactive 节点：标题前缀、粗体/斜体 marker、行内码 marker、链接语法生成 `Decoration.replace`；正文生成 `Decoration.mark`。
- 光标或选区触及完整 Markdown 节点时，该节点不产生装饰，原始标记自然恢复。
- 可见区使用半开区间相交规则；语法树只遍历一次，跨两个 visible range 的节点不会重复生成装饰。
- 所有 replace 范围同时形成 `EditorView.atomicRanges` provider；测试核对 provider 返回的 RangeSet 与隐藏 marker 一一对应。

### IME 组合期冻结

- `composing=true` 且仅 selection 变化：复用原 DecorationSet，不 rebuild。
- 组合期 doc change：只通过真实 `ChangeDesc` 映射既有 decoration/atomic range，不解析新输入。
- `compositionend` 后即使是空 update，只要上一状态为 `frozen/frozen-mapped` 就强制 rebuild。

这证明装饰层可以避免在 composition 期间主动拆重 DOM，但不能替代真机中文输入法候选框视觉验证。

### 外部写回与 history

- controlled value 写回采用最长公共前后缀计算最小中段 diff。
- transaction 标注 `Transaction.addToHistory=false`。
- 真实 CodeMirror history 验证：一次用户输入后 `undoDepth=1`，外部写回后仍为 1；selection 按 change mapping 保留、不重置到 0；随后 undo 仍撤销此前用户输入。
- 值未变化返回 `null`；纯装饰重算不创建 transaction。

## 验证

```bash
npx tsx --test src/__tests__/unit/live-preview-poc.test.ts
npx tsc --noEmit
```

结果：**11 tests / 3 suites / 0 fail**；TypeScript 通过。
全量 `npm run test` 同步通过：**3851 tests / 964 suites / 0 fail**。

首次运行暴露的三个问题都属于测试断言错误，已修正并保留判断过程：

1. fixture 把光标放在文档末尾，按 inclusive reveal 契约会激活末尾链接；改到普通文本位置。
2. 把 `ChangeSet.toJSON()` 压缩格式误当普通数组；改用 `iterChanges` 断言真实区间。
3. selection 期望误写成“必须落文档末尾”；改为断言 CodeMirror 的真实 change mapping 且不归零。

首次 commit 的真实 pre-commit 随后暴露另一处仓库级问题：`pre-commit-tier.test.ts` 在 hook 内创建临时 Git 仓库时继承了 repository-local `GIT_*` 环境，临时 `git init` 实际把主仓库 `core.bare` 改为 `true`，导致全量结果 3849/3851、随后 `git status` 也无法运行。这不是 flaky。处理：

- 用 `git rev-parse --local-env-vars` 动态取得完整变量集合，并额外剥离 `GIT_NAMESPACE`。
- 临时 repo 的 `git` 与调用分类脚本的 `node` 子进程统一使用清理后的环境。
- 新增两条 guardrail：动态断言全部变量被清除；模拟外部 `GIT_DIR/GIT_WORK_TREE/GIT_INDEX_FILE` 污染，证明目标 cwd 正常初始化而外部 repo 的 `core.bare`、commit 数与 sentinel 内容不变。

修复后 `pre-commit-tier.test.ts` + Live Preview POC targeted 合计 **28/28**，TypeScript 通过。
